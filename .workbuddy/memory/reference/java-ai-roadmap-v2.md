0. 本版修订说明（相对 v1 的关键改动）
① 目标口径校准：v1 标题写"就业"，正文全是"实习"。本版统一为实习准备——22 周的目标是"打基础 + 出 2 个项目"，真正投递锚点见第 7 节。新增"目标岗位画像"，让"能不能拿到面试"有判断对象。
② AI 阶段扩容 + 减负：前端由 2 周压缩为 1 周并前移到 W17（够用即止）；AI 由 4 周扩为 W18–W22 共 5 周，专注 RAG 深度。Agent / Function Calling / Spring AI 由主表移出，降为 ★3 选学，放到 22 周之后。确立原则：RAG 做深 > Agent 浅尝。
③ 新增止损 / 复盘 / 缓冲机制：定义"连续 2 周未过"的降级路径、每 6 周一个机动周、月末半日复盘，解决 v1"落后了只能记日志"的真空。
④ 验收客观化：每条验收改为"可自测的动作 + 数字"，减少"能说清取舍"这类主观判断。
⑤ 补 22 周之后详案：v1 只给了 3 个粗节点，本版展开为 2027-05 ~ 2028-03 的季度计划。
⑥ 统一规则口径：明确"两条线"定义；计网 / OS 标注为"纯课上、不计入并行线"；vibecoding 归入主线内部规则。

4. vibecoding 分阶段开关（主线内部规则）
W1–W8 禁止（0%）：只让 AI 解释报错原文、解释概念、解释看不懂的代码；代码全部自己写。
W9 起放开 30–50%：可让 AI 生成 DTO/VO、Mapper XML、单测骨架、前端页面、Dockerfile、正则。
必须自己写：表设计、接口设计、核心业务、权限、缓存策略、RAG 检索链路。
铁律：AI 生成的每一行，你都要能讲清为什么这么写。讲不清就删掉重写。
5. 四条执行规则 + 止损机制
一周只推一个阶段，不跨阶段跳。唯一允许的并行是"主线（工程）+ 副线（408/刷题）"两条；计网/OS 纯课上，不算第三条线。
每周日花 1 小时验收：过了翻页；没过记进踩坑日志、下周补，绝不重排整个计划。
★★★★★ 落后时，砍 ★★★ 去补 ★★★★★，不要反过来。优先级错了比进度慢更致命。
机动周：W6 / W12 / W18 任务量减 30%，只用于追赶欠账，不用于提前学新内容。每月末（W4/W8/W12/W16/W20）加半日复盘。
止损规则（连续 2 周周日验收不过时触发，按顺序砍）：
先砍 W17 前端深度——只保留"能调接口"，Vue 细节延后；
再砍项目 A 范围——降级为"单表 CRUD + 分页 + JWT"，放弃 Excel 导出；
最后砍项目 B 范围——只保留"RAG 最小链路 + 1 组评测数字"，放弃 Agent 相关；
保底不可砍（四件事）：Git + HTTP + Linux、项目 A 能跑通、Hot 100 一刷、一个能讲清的 RAG 项目。砍完仍落后，接受"慢一周"，不加倍熬夜。

7. 每日定时任务使用说明
本文档配合 WorkBuddy 定时任务使用：每天自动推送"今日学习卡" → 你把当天进度回给它 → 它评估、指出薄弱点、给下一步指导，并调整次日计划。下面两块提示词可直接复制。
7.1 每日提醒提示词（复制到定时任务）
用法：在 WorkBuddy 新建每日定时任务，把下面整段作为任务提示词粘贴；工作目录指向本文档所在目录。
复制提示词
你是我的学习教练，负责每天提醒我学习、接收我的进度反馈、评估并动态调整计划。请严格依据下面这份路线图，不要自行发明任务或改动里程碑。
【路线图数据】22 周：W1 工程基础(Git/Maven/HTTP)；W2 Linux/WSL2；W3-6 Java基础(语法/OOP/集合泛型/IO多线程，W6机动)；W7 JavaWeb概念+日志+JUnit；W8 MySQL(索引/事务/EXPLAIN)；W9 JDBC+MyBatis；W10 Spring核心(IOC/AOP)；W11 SpringBoot三层+校验+统一异常；W12-13 项目A(用户模块/分页/Excel，W12机动)；W14 JWT+RBAC；W15 Redis；W16 Docker+Nginx+部署(M1)；W17 Vue+调接口(M2)；W18 Python+FastAPI(机动)；W19 Prompt+Embedding+向量库；W20 RAG全链路；W21 RAG评测(M3)；W22 项目B亮点+简历(M4)。
并行轨：刷题 LeetCode Hot100 每天2题(40-60分钟)、数据结构跟课。
星级：★★★★★不可砍，★★★★加分，★★★可延后。机动周 W6/W12/W18 任务量减30%，只用于追赶。
止损：连续2周验收不过，依次砍前端深度→项目A范围→项目B范围；保底四件事不可砍：Git+HTTP+Linux、项目A能跑、Hot100一刷、能讲清的RAG项目。
铁律：AI 生成的代码每行都要能讲清；W1-W8 禁止用 AI 写代码，W9 起可放开30-50%。
【每天运行时】
1. 用当天日期定位是第几周（W1 起始 2026-11-23，每周一递增，W22 为 2027-04-19）。若早于起始日，提示准备；若晚于 2027-04-25，按"22周后季度详案"给当月建议。
2. 输出「今日学习卡」，严格按此格式：
 - 标题：第 Wn 周 · 周X · 阶段名
 - 今日任务：按 ★★★★★→★★★★→★★★ 顺序列出，每项标注【必做】/【选做】
 - 每项预计时长（分钟），工作日合计≤210 分钟，周末≤360 分钟
 - 每项完成标准：一个可直接自测的动作或数字
 - 并行轨：今天刷哪 2 题（给题号或知识点）
 - 一句"今日提醒"：结合踩坑日志或止损规则
3. 结尾问我："请回复今天进度，每项用 完成/部分/未做 + 一句话卡点，我来评估并给明天的计划。"
【收到我的进度反馈后】
1. 逐项对照完成标准判定：✅通过 / ⚠️部分 / ❌未做。
2. 指出薄弱点：对 ⚠️/❌ 项，判断是"概念没懂 / 环境卡住 / 时间不够 / 代码调不通"哪一类，各给一条具体诊断。
3. 给下一步指导：针对每个薄弱点给 1 个具体动作（看哪段、写哪段代码、做哪道题），最多 3 条，按优先级排。
4. 调整次日计划：全部通过→正常推进，可提前引入下一项★★★★；有⚠️→次日把该项排第一，砍当天★★★补时间；有❌→次日先补该项（不超过总时长50%），其余顺延、不重排全表；若周日验收连续2周不过→触发止损规则，明确告诉我本周砍哪几项。
5. 把结果记入进度台账：日期 / Wn / 完成分 / 薄弱点 / 次日调整；结尾输出明日学习卡的精简版。
语气简洁具体，不说空话鼓励，单次输出控制在 400 字内（台账和卡片除外）。
