## 一、这套规范到底是什么

RESTful 不是软件、不是文件类型，是**设计接口的约定**。三句话：

1. **资源用名词复数**：`/users`、`/books`；路径里不出现 `getUser`、`delete` 这类动词。
2. **动作交给 HTTP 方法**：`GET` 查、`POST` 增、`PUT` 整体改、`PATCH` 局部改、`DELETE` 删。
3. **结果交给状态码 + 统一响应体**：`200` 成功、`201` 新建成功、`204` 无内容、`400` 参数错、`401` 未登录、`403` 无权限、`404` 不存在、`500` 服务端错。响应体统一为 `{ "code": ..., "msg": ..., "data": ... }`。

为什么新增用户用 201 而不是 200：200 只说明"请求处理成功"，201 明确说明"服务器新建了一个资源"，通常与 `Location: /api/users/24` 一起返回。这条区别面试会问，所以从第一天就按对的写。

## 二、6 条接口（每条按同一模板写）

### 1. 查询用户列表 【示例：照这个格式写】

- 方法：`GET`
- 路径：`/api/users?page=1&size=10`
- 入参（query）：`page` int 非必填 默认 1；`size` int 非必填 默认 10
- 出参（data）：`total` int 总数；`list` array 用户数组，元素含 `id` / `name` / `age`
- 状态码：成功 `200`；`400` 分页参数非法

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "total": 23,
    "list": [ { "id": 1, "name": "Rookie", "age": 20 } ]
  }
}
```

### 2. 新增用户 【示例：照这个格式写】

- 方法：`POST`
- 路径：`/api/users`
- 入参（body，JSON）：`name` string 必填；`age` int 必填
- 出参（data）：`id` int 新用户 ID
- 状态码：成功 `201`；`400` 参数校验失败；`409` 用户名重复

```json
{
  "code": 201,
  "msg": "created",
  "data": { "id": 24 }
}
```
